## 2. What was built this session

### B3 — `forward_outcomes` short horizons (4 increments)
New **separate forward pass** `bin/write-forward-outcomes` with a ~6-day ring
buffer (the chronological B1/B2 sweep is untouched). Engine module
`crates/momentum-engine/src/forward_outcomes.rs`. For the 8 short horizons
(`10min,30min,60min,EOD,1d,2d,3d,5d`) × 17 entry offsets:
- identity + entry pricing, all pre-entry parametric features (incl.
  cross-sectional ranks + `cumulative_volume_to_entry`), entry-quality proxies;
- per-horizon ret / drawdown / runup / close-extremes / bars-to-extreme;
  `ret_<H>_excess_{spy,qqq,iwm}`;
- fixed-% + ATR threshold crossings (1-based bar index; 0 = never; null = truncated);
- `hit_`/`first_event_` target-before-stop labels (8 of 9 pairs);
- day-0 `ret_to_<seg>` segments + post-entry session-shape; close-based
  time-underwater; next-day outcomes; gap-vs-RTH days 1–5.

### B4 — `forward_path_short` (1 increment)
Long-format path table, 19 columns × 23 checkpoints (1m → 5d_close), incl. the
4 v2 Markov-state columns. Engine module
`crates/momentum-engine/src/forward_path.rs`. **Written in the same pass** as
`forward_outcomes` (one ring-buffer walk → both tables). Cross-table invariant
verified: `fp.ret` at aligning checkpoints == `forward_outcomes.ret_<H>`.

### B5 — multi-day horizons + dividends + terminal events (2 increments + 1 fix)
New **forward daily-aggregate matrix** preload (the 6-day ring buffer can't
reach 252 days): pin-adjusted close/high/low per security over
[first entry, last entry + 252 trading days], + pin-adjusted dividend lookup +
delisting lookup.
- 10d–252d horizons at **daily resolution** (stats + daily crossings + the 21d
  label); `bars_to_*` in trading-day units;
- `ret_<H>_total` (dividend-adjusted) + `dividend_ex_date_within_<H>`;
- `bar_gap_minutes_max` (≤5d from the 1m tape; null for 10d+);
- **terminal events** — `delisted_unknown` only (no delisting reason on disk;
  merger/bankruptcy never claimed), with date / return / last-valid-trade-date /
  days-missing / confidence.

## 3. Bugs found & fixed (the track record)

**Real engine-data bugs (output would have been wrong):**
1. **B5 vendor sid-collision honesty bug** — one composite FIGI shared by two
   securities (e.g. AJX/RPT) got one-listing-arbitrary forward values; the B5
   daily matrix and the B3/B4 1m tape picked *different* listings. **Caught by
   the B5 E2E suite, after the initial B5 commit.** Fix: forward outcomes are
   null for collided sids (~17/day), matching `daily_observation`. Re-swept.
2. **B3 cross-day split-basis rescale** — would have corrupted return windows
   straddling a split. **Caught by reasoning before any B3 commit** (no bad data
   shipped). Removed the rescale; verified against raw price × split ratio.

**Validator/test bugs (engine was correct; the check was wrong):** B3 half-day
fill cap (validator side), B4 "23 rows" invariant too strict for collided sids,
B5 `_md_dividends` date type + `_md_daily` cache starvation, a B3 L1 test sitting
on an f64 threshold boundary.

### Honest confidence read
- **High** for the 144 swept days — four independent layers agree and keep
  catching bugs.
- **Moderate** for generalizing to the full corpus, until B6: the smoke window
  is calm 2016-H2; the stress regimes a bot must survive (2020 COVID, 2021 meme

  **unvalidated**. Full-universe exact recompute is also a gap (most L2 exact

3. **Re-run the full battery on stress regimes** (a halt day, the rename day,
   the split day, a 2020 COVID week) — closes the coverage gap, the dominant risk.

### Before any real capital (beyond B6)
- A few **hand-audits against an external source** (Bloomberg/Yahoo) end-to-end
  on volatile names — pure outside truth, zero shared code.
- **Live shadow / paper-trade** any candidate before a dollar (strategy doc §5
  step 9) — the future is the only uncontaminable data.

### The bigger picture
Phase 0 only guarantees the data is **recorded correctly**. The bot's edge rides
on **Phase 1** (not started) — and the strategy doc (§1.5.1) is explicit that
this dataset is only powered for Sharpe ≈ 1.5–2 edges, so the likely deliverables
are a **blacklist** and a **characterized null**, not a deployable edge. Correct
data ≠ a profitable bot.

## 6. How to run things

```bash
# Forward pass (writes BOTH forward_outcomes + forward_path_short).
# Run AFTER write-phase0 (it reads daily_observation[D] for entry context).
cargo run --release --bin write-forward-outcomes -- --from 2016-06-08 --to 2016-12-30 --force

# Full B-table sweep order:
#   build-earnings-calendar → write-phase0 → write-forward-outcomes → build-regimes

# Validation (full battery ~10 min; or one day).
scripts/validate_phase0_outputs.py
scripts/validate_phase0_outputs.py 2016-09-15

# Tests + lint.
cargo test --workspace
cargo clippy --workspace --all-targets
```

**Working-style notes:** build `--release` for sweeps; run long sweeps in the
background (a 144-day forward sweep is ~40 min incl. the ~70s daily-matrix
preload); the §4.5 gate is non-negotiable (validator coverage lands in the same
commit as engine code, every diff adjudicated); honest nulls over fabricated
data (the collision fix is the latest example).
